# InputWatchDog

マウス操作・キー入力が「たまに」効かなくなる現象の**原因特定を支援する**常駐監視ツールです。

## できること／できないこと

- **できること**：OSに実際に届いた入力イベント、システム負荷、ウィンドウの応答性、
  USB着脱、電源状態の遷移などを継続的にログへ記録し、症状発生時刻付近の状況証拠を集約する。
- **できないこと**：「入力が反映されなかったこと」自体を自動検知することはできません。
  無かったことはログに残らないため、症状に気づいた瞬間に**手動マーキング**（後述）を
  行ってもらうことが前提の設計です。

## 使い方

1. 管理者権限で `InputWatchDog.exe` を起動する（自動的にUACの昇格を求められます）。
   - 管理者権限で動作しているウィンドウを操作中は、非管理者権限の低レベルフックには
     イベントが届かないため、本ツール自体も管理者権限で動かす必要があります。
2. タスクトレイに常駐します。通常業務を継続してください。
3. **「入力が効かなかった」と感じた瞬間に `Ctrl + Alt + M` を押してください。**
   （トレイアイコンの右クリックメニューからも実行可能）
   - マーキング時刻の前後（-20秒〜+10秒）のイベントを集約したレポートが
     `Data\MarkReports\mark_yyyyMMdd_HHmmss.txt` に自動生成されます。
4. 生じたレポートには、下記の分類ロジックによる「疑わしい原因カテゴリ」の目安が
   自動で記載されます。数回分のマーキングを集めて傾向を確認してください。

## 原因分類の目安

| ログの状態 | 疑われる原因 |
|---|---|
| フック・RawInput共にイベントが来ていない | デバイス／ドライバ／受信機の問題（電池切れ、無線干渉、USBセレクティブサスペンド） |
| フックとRawInputで検出結果に差異がある | 他プロセスのフック介入（IME、セキュリティソフト、リモート操作ツール等） |
| イベントは来ているが画面に反映されない | フォアグラウンドウィンドウのハング（アプリ側の問題） |
| USBデバイスの着脱イベントと重なる | 物理的な接続不良、USB電源管理設定 |
| CPU使用率90%以上のログと重なる | システム高負荷によるメッセージポンプ遅延 |
| サスペンド/レジュームのログと重なる | 省電力設定によるデバイス休止 |

## ログの保存先

- `Data\Logs\input_yyyyMMdd.csv` … 全イベントの継続ログ（起動している限り常時記録）
- `Data\MarkReports\mark_*.txt` … マーキング時の相関レポート

## 既知の制限事項

- ワイヤレスデバイスの受信機・ドライバ内部で起きている欠落は、OS APIからは
  見えない場合があり、本ツールでは検知できないことがあります。
- 管理者権限で動作する別アプリの操作時は、フックの取得状況が変わる場合があります。
- 常時ロギングのため、`Data\Logs` は放置すると肥大化します。定期的に確認・削除してください。

## ビルド

```
dotnet build InputWatchDog.csproj -c Release
```

## テスト

`tests\InputWatchDog.Tests.csproj`（xUnit）にユニットテストがあります。

```
dotnet test tests\InputWatchDog.Tests.csproj
```

### テスト対象・対象外について

- 対象：`InputEvent`（CSV整形）、`MarkAnalyzer.Classify`（原因分類ロジック）、
  `Logger`（リングバッファへの記録・時間範囲検索・保持期間超過分の追い出し・CSVファイルへの書き込み）
- 対象外：`HookMonitor` / `RawInputMonitor` / `SystemHealthMonitor` / `MainForm` は
  Win32 API（低レベルフック、Raw Input、UI応答性チェック等）に直接依存しており、
  実OS環境でのフック登録やウィンドウメッセージが前提のため自動テストの対象外としている。
  これらは `README.md` の「使い方」に沿った実機での動作確認で担保する。

## 配布用の発行（dotnet publish）

配布先の端末に他部署のPC等、.NET 8ランタイムの有無が分からない場合は、
**自己完結（self-contained）＋単一ファイル**での発行を推奨します。
ランタイムがインストール済みと分かっている端末には、**フレームワーク依存**の発行で
ファイルサイズを抑えられます。

### 自己完結・単一exe（.NET未インストール端末向け）

```
dotnet publish InputWatchDog.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o ./publish
```

- `.\publish\InputWatchDog.exe` 1本のみで配布可能（約140MB。WinForms/WPFランタイム同梱のため）
- 発行先の端末に .NET ランタイムのインストールは不要

### フレームワーク依存・単一exe（.NET 8 デスクトップランタイム導入済み端末向け）

```
dotnet publish InputWatchDog.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o ./publish
```

- `.\publish\InputWatchDog.exe`（約200KB）のみで動作
- 発行先の端末に **.NET 8 Desktop Runtime (win-x64)** のインストールが必要

### 注意事項

- `app.manifest` で `requireAdministrator` を指定しているため、
  発行したexeを実行すると常にUAC昇格が求められます（想定どおりの挙動）。
- `-r win-x64` を環境に応じて `win-x86` / `win-arm64` に変更可能。
- 発行後は `publish` フォルダを丸ごと配布してください（単一ファイル化していても
  `.pdb` は分離されるため、デバッグ不要なら除外して構いません）。
